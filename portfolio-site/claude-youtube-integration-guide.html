Claude × YouTube Integration Guide

A practical guide to transcripts, channel research, analytics and publishing with Claude. Choose tools by the data and actions they actually expose.

4. Choose the right route

Match your goal to the required input
GoalStart withCheck the output
Understand a spoken explanationCaption transcript, pasted or fetchedLanguage, timestamps and missing passages
Review editing or on-screen eventsA tool explicitly supporting visual video analysisWhether it received video, frames or only captions
Research other creatorsPublic research tools such as vidIQSource links, observation date and estimates
Explain your channel’s performanceAuthorized channel analytics or an exported reportCorrect channel, date range and available metrics
Upload or schedule a videoA publishing connector with your channel connectedActual video ID, visibility and scheduling result

A YouTube URL alone does not prove that Claude retrieved the video. Ask which tool ran and what it returned. A transcript can support a summary of speech, but cannot by itself establish visual pacing or on-screen details. Actual capability depends on the selected tool.

References: transcript server, vidIQ.

5. Start without installing anything

  1. Open a captioned video on YouTube and expand its description.
  2. Select Show transcript. Check the language and a few lines against the spoken audio.
  3. Paste the relevant transcript into Claude with the video title, URL and your question. Keep timestamps when available.
  4. For a long video, send numbered parts and ask Claude to wait until the final part before summarizing.
Using only this transcript, summarize the main argument in five points. Give timestamps where provided. Separate the speaker’s claims from your interpretation, and list gaps you cannot resolve from the text.

For a video without available captions, this route will not provide a transcript. If you have an authorized media file, a separate transcription tool may be needed. Do not replace missing passages with guesses.

Source: YouTube transcript instructions.

6. Connect a hosted service to Claude

Claude web or Desktop: remote connector

  1. Open Customize → Connectors (some versions use Settings → Connectors).
  2. Choose the directory listing or add a custom connector. For custom vidIQ, enter https://mcp.vidiq.com/mcp.
  3. Review the detected authentication method and finish the provider’s sign-in flow.
  4. Enable the connector in the conversation if it is not already enabled.
  5. Make one small read request and confirm an actual tool result appears.

A remote connector is reached from Claude’s cloud, so a localhost address is not a replacement for a publicly reachable provider endpoint. Organization policy may restrict who can add connectors.

Source: Claude custom connector setup.

Claude Code: terminal setup

With Claude Code installed, run:

claude mcp add --transport http vidiq https://mcp.vidiq.com/mcp
claude mcp list
claude mcp get vidiq

Inside Claude Code, enter /mcp to inspect the connection and complete authentication where supported. A saved configuration is not the same as a successful tool call. These commands configure Claude Code; they are not instructions to paste into a normal web chat.

Source: Claude Code MCP reference.

7. Use a local transcript server

The community project below documents a local Node/npx server. Install Node.js first if node --version and npx --version do not work. Review the maintainer’s instructions before running a community package.

For a Claude Desktop installation supporting local MCP JSON configuration, add this entry to its MCP configuration, preserving your other servers:

{
  "mcpServers": {
    "youtube-transcript": {
      "command": "npx",
      "args": ["-y", "@kimtaeyoon83/mcp-server-youtube-transcript"]
    }
  }
}

Restart the client after saving. If it already contains mcpServers, merge the inner server entry rather than creating a duplicate key. This local setup is separate from the remote-connector form.

Ask for get_transcript with your video URL, lang: "en" and include_timestamps: true. Set strip_ads: false when you need the full text, because the documented default filters promotional passages. The transcript function does not require the optional TwelveLabs key.

Source and installation updates: Maintainer’s README. The earlier unscoped package command has been replaced with this documented package name.

8. Research and channel analytics

vidIQ supports research and analytics workflows. Its Claude directory connection and custom connection expose different tool sets; the directory version excludes some creation and video-change tools. Use the provider’s feature list to choose. vidIQ credits and the Claude subscription are separate.

For your channel, verify the connected channel identity before requesting private analytics. For another creator, label public observations and estimates rather than treating them as private retention or revenue data.

Source: vidIQ MCP setup and capability list.

A useful audit specification

Analyze my connected channel for the last 28 complete days against the preceding 28. State exact dates and timezone. Separate Shorts, long-form videos and livestreams. Return available metrics with source and retrieval time. Mark unavailable fields as unavailable. Recommend three experiments with one measurable outcome each.

Compare like with like: a new upload has had less time to collect views than an older one. Ask for comparable upload-age windows when possible. Treat a proposed explanation as a hypothesis until the data supports it.

If you build your own integration

YouTube’s Analytics API supports targeted reports; the Reporting API supports bulk reports. A custom integration needs the appropriate authorization and supported metric/dimension combinations. An MCP server supplies the assistant interface; it does not remove Google’s access requirements.

Source: YouTube Analytics and Reporting APIs.

9. Set up publishing separately

Blotato documents the endpoint https://mcp.blotato.com/mcp. Connect it through Claude’s custom connector flow, authorize your Blotato account, then ask it to call blotato_list_accounts. An empty account list can mean authentication worked but no social account is connected.

Connect the intended YouTube account in Blotato before publishing. Its documentation states that MCP/API access requires a paid subscription and is not included in the free trial; generating an API key during the trial starts billing.

For local media, the documented flow requests a presigned upload URL, uploads the raw bytes using HTTP PUT, then passes the returned public media URL to the posting tool. A path on your laptop is not a remotely accessible video URL.

Source: Blotato client setup and upload flow.

Suggested release workflow

  1. Prepare: select the exact media file and destination channel. Draft the title, description and thumbnail brief.
  2. Check capability: ask which current tool supports each required field. Do not assume support for chapters, custom thumbnails or scheduling.
  3. Review: inspect the final title, audience setting, visibility and scheduled date with timezone. Use private or unlisted visibility for a test if the provider supports it.
  4. Approve: authorize the exact upload or update after reviewing the values.
  5. Verify: record the returned job/video ID, check processing status, and inspect the result in YouTube Studio. A queued job is not proof of publication.
Prepare a publishing proposal for this video. Show the destination channel, title, description, visibility, audience setting, media source and scheduled time. List unsupported fields. Do not submit until I approve the final values.

For a direct Google implementation, videos.insert handles uploads with authorization. Google documents restrictions on uploads from unverified API projects; check the current reference before relying on public publishing.

Source: YouTube upload API.

10. Reusable prompts

These are suggested task specifications, not guarantees that every connector has the required tools.

Video breakdown

Retrieve the transcript for [URL]. Confirm the title and language. Map the opening hook, key claims, examples and conclusion with timestamps. Analyze only retrieved material and identify what requires visual inspection.

Original content ideas

Research five relevant public videos about [topic] for [audience]. Include URLs and observation dates. Identify unanswered questions, then propose three original angles. Separate measured facts from your interpretation.

Title improvement

Using this transcript and intended audience, draft five accurate titles. Explain the specific promise in each. Avoid claims the video does not support. Keep these as drafts.

Small first connection test

Using the connected service, retrieve the title and available transcript for [URL]. Tell me the tool used, whether it succeeded, and whether the result is complete. If a capability is missing, stop and name it.

11. Troubleshoot by symptom

SymptomCheck next
Connector added, no tools availableConfirm authentication and conversation enablement. In Claude Code inspect /mcp and claude mcp get vidiq.
Local server will not startCheck Node/npx availability, JSON syntax and the client’s MCP logs. Confirm you used the documented package name.
Transcript missing or incompleteCheck whether captions exist in YouTube, which language was returned, and whether filtering was enabled. Report missing text explicitly.
Public research works, channel analytics do notVerify the connected channel and permissions. Request a small supported report before a full audit.
Authentication or subscription errorRead the returned provider error. Confirm the account, authorization and plan; do not keep retrying the same failed request.
Upload fails with a local file pathUse the provider’s upload flow first. Verify that the returned media URL is the one passed to the publishing action.
Published twice after a timeoutInspect the first job’s status before retrying. Keep job IDs so an uncertain response does not become a duplicate submission.

When asking for help, include the client, connector name, attempted operation and redacted error. Keep API keys and authorization tokens out of screenshots, prompts and shared configuration.

12. Frequently asked questions

Does a transcript mean Claude watched the video?

No. It shows access to caption text. Ask a visual-analysis tool for on-screen evidence when the question concerns camera work, graphics or editing.

Do all routes need a YouTube API key?

No. Manual transcript use and the documented community transcript function do not. Hosted services manage their own integration requirements; access to your channel may require a separate account connection.

Can I use one connector for everything?

Only if its available tools cover every required action. Verify transcript access, analytics and publishing individually. Being connected does not imply permission to publish.

Will this keep running on a schedule?

Not merely because a connector was added. A recurring workflow needs a scheduler or supported automation feature, credentials that remain valid, a defined destination and a failure-reporting path.

What should I save with an analysis?

Keep the video URLs, exact date range, channel identity, retrieval time, data limitations and proposed actions. This makes the next comparison reproducible.
