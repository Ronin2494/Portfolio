### Major open defect — P1 mobile performance
Issue: [#13](https://github.com/Ronin2494/Portfolio/issues/13).
- Hero heading `#portal-copy > h1` is the LCP element. About **91%** of its ~7.29 s loading time occurs as render delay (~6.65 s).
- Long tasks observed: `neural-field.js` ~377 ms, `movement-tracker.js` ~288 ms, Google AdSense JS ~232 ms.
- Render blocking: Google Fonts CSS and `scene-image.css` (Lighthouse estimated savings). Two AdSense scripts account for ~150 KiB unused JS.
- Preserve scroll-synchronized neural rendering, reversible hero scroll, Bento asymmetry and modal UX while remediating. Re-test mobile performance after every code change.

### Accessibility diagnostics
Axe detected **three issues in a YouTube-owned embedded iframe** on the homepage:
- `aria-allowed-attr` (critical): video title markup uses unsupported `aria-level`.
- `aria-prohibited-attr` (serious): iframe player div has disallowed `aria-label`.
- `button-name` (critical): channel avatar button without accessible name.
All three target selectors start with `iframe[loading="lazy"]`. These are third-party iframe DOM; Portfolio cannot directly modify the provider's controls. Do not label the full page as clean without this caveat.
Lighthouse separately flagged **label-content-name-mismatch** diagnostic on some first-party navigation labels; it is not reflected in the weighted score (100). Track accessible names and keyboard experience in subsequent remediation.

### Best practices
Lighthouse score **79 mobile / 78 desktop** is chiefly reduced by a third-party Google AdSense cookie diagnostic and associated Chrome DevTools cookie issue. Review consent / load strategy without silently removing monetization.

## Not verified and remaining release risks
1. **Real PayPal** sandbox/live checkout, approval, capture, double-click protection, webhook/fulfillment/refunds — requires controlled provider credentials/test account; do not create real charges during QA.
2. **Firebase** email-link login/expiry, creator authorization, studio upload/publish/delete, end-to-end Mongo persistence — requires authenticated test identities.
3. **Real iOS Safari, Android Chrome, desktop Firefox/WebKit** hardware/browser compatibility beyond Chromium emulator.
4. **Actual video playback** under provider/geo/network restrictions. Thumbnail DOM tests verify image elements, not every remote image's availability.
5. **Screen reader testing** (VoiceOver, TalkBack, NVDA), manual keyboard walkthrough and visual comparisons.
6. **Production traffic load, payment security penetration test, CWV field data** and full Catchpoint WebPageTest for this actual site. Supplied Catchpoint URL is not evidence for badbunny.work.

## Method and next actions
- Keep regression tests and browser smoke in CI and upload artifacts for every relevant PR. Run the performance audits as read-only diagnostic checks.
- Treat PASS, FAIL and NOT VERIFIED separately. No payment or credential side effects are triggered by this audit.
- Remediate P1 performance first, then repeat mobile Lighthouse, ensure no hero interaction regressions, and evaluate remaining device/account scenarios.
